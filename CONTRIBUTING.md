# Contribuir

1. Ler `RULES.md` e `AGENTS.md` antes de alterar o projeto.
2. Trabalhar numa fase/tarefa aprovada de `specs/001-travel-propose-mvp/tasks.md`.
3. Manter cada PR abaixo de 400 linhas; dividir trabalho maior antes de implementar.
4. Usar TDD para comportamento novo e executar as verificações aplicáveis.
5. Inspecionar `git diff --staged` antes de cada commit.
6. Usar Conventional Commits e abrir PR para `main` com CI verde.
